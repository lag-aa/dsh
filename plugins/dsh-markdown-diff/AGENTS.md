# dsh-markdown-diff

## Что это

Локальный плагин DSH Desktop: подсветка изменений git в правой панели просмотра Markdown.

Файл `.md` в правой панели открывает вкладка `editor` плагина `dsh-better-sidebar`: её тип
зарегистрирован с шаблоном `dsh-resource://file/**` в полосе `extension`, поэтому адрес
достаётся ей, а штатный предпросмотр документов (`fallback`) до выбора рендерера не доходит.
Точка расширения, которую этот плагин сам объявляет, — `registerFileViewer`: просмотрщики
ранжируются по убыванию `priority`, а свой Markdown-просмотрщик он регистрирует без
приоритета. Поэтому плагин регистрирует **свой просмотрщик** `md`/`markdown` с `priority: 10`
через сервис `betterSidebar` — это и есть перехват, без борьбы шаблонами.

Второй регистрацией остаётся рендерер документа для `.md`/`.markdown` с
`priority: 'extension'`: он срабатывает, когда вкладка сайдбара недоступна и адрес забирает
штатный предпросмотр. Все откаты (нет репозитория, нет изменений, файл не дочитан, файл
слишком велик) рисует сам плагин. Исключение — режим «Без подсветки» в файловой вкладке:
там документ рисует встроенный просмотрщик сайдбара, см. `ShippedPlain` в «Карте».
Ставится только в профиль `desktop`; дистрибутив DSH не патчится.

## Карта

- `lib/index.js` — хост-часть (руками): маршруты `GET /api/markdown-diff.base` и
  `GET /api/markdown-diff.refs` внутри `ctx.connection.fetch`; id сессии → корень
  воркспейса, git запускается на хосте.
- `lib/base.js`, `lib/git-run.js` — руками: чтение базы сравнения (`git show HEAD:<path>`,
  `git show :<path>` или `git show <sha>:<path>`) и запуск git.
- `lib/refs.js` — руками: список ветвей, разрешение имени ветки в SHA (имя из браузера
  никогда не попадает в аргументы git) и `merge-base` для точки ветвления.
- `src/MarkdownDiffBody.js` — руками: `MarkdownDiffViewer` (просмотрщик файловой вкладки) и
  `MarkdownDiffBody` (рендерер документа) — обе оболочки над общей `DiffSurface`.
  Просмотрщик отдаёт вкладке `onToolbarState`/`onToolbarControls` (иначе шапка теряет
  правку, сохранение и «Обновить») и умеет уступить файл встроенному редактору сайдбара:
  тот берётся из публичного `betterSidebar.getFileViewers()` по `id === 'markdown'` и
  рисуется как есть, с подменой только `setMode`. Тот же дескриптор рисует режим
  «Без подсветки» целиком (`ShippedPlain`): скрытие frontmatter и кнопка «Добавить в
  диалог» живут только внутри `TextEditor` и приватны, поэтому режим делегируется, а не
  имитируется. Свой `plainDocument` остаётся на случай, когда встроенного просмотрщика нет.
  Ведущий frontmatter в diff-режимах рисует `Frontmatter` — складка со свойствами, а не
  `<pre>`: сворачивание живёт состоянием поверхности (`frontmatterCollapsed` в
  `DiffSurface`), а не блока, потому что две половины изменённой группы сравниваются по
  тексту, и по-разному свёрнутые половины сбили бы подсветку слов. Свёрнутый блок прячет
  строки через `display:none`, а не удаляет их из дерева.
  Комментарии к выделению живут здесь же: `DiffSurface` держит состояние (`anchor` —
  плавающая кнопка у выделения, `comment` — открытая область ввода, `marks` — уже
  отправленные замечания), слушает `selectionchange` и рисует кнопку абсолютно внутри
  своего корня. Порталов нет: таблица модулей даёт только `React`, `ReactDOM` плагину
  не положен. Дифф считается до первого раннего возврата — эффекту выделения нужны
  группы, а хук после ветвления даёт React #300.
- `src/comments.js` — руками: формулировка комментария (адрес `путь[:строки][ · старая
  версия]`, цитата, метка замечания, текст сообщения) и сопоставление выделения со
  строками исходника. Чистые строки, без DOM. Выделение ищется в Markdown блока; не
  нашлось или нашлось дважды — адрес берётся по границам блока, а не угадывается.
  Сообщение всегда одно и то же: адрес, цитата, замечание за меткой — встык, без
  пустых строк, и с одним переводом строки в конце. Цитата — ограждённый блок, а не
  blockquote: в blockquote замечание из-за lazy continuation отрисовалось бы внутри
  цитаты, а ограда закрывается своей линией при любой следующей строке. Ограда
  длиннее самого длинного ряда обратных кавычек внутри (и не короче трёх), иначе
  цитата кода закрыла бы себя сама. Метка `**Замечание:**` отделяет слова читателя от
  цитаты. Выделение длиннее `SELECTION_LIMIT` (500) не цитируется: остаются адрес и
  замечание.
- `src/selection.js` — руками: чтение выделения из DOM (`data-dsmd-group` на блоке,
  `data-dsmd-side`/колонка — половина группы) и координаты кнопки относительно корня.
  `BTN_OFFSET` — отступ кнопки от текста; он же обязан совпадать с шириной
  `.dsmd-commentBtn` в стилях (это сверяет `test/styles.test.mjs`), иначе кнопка либо
  накрывает первые буквы строки, либо уезжает от неё.
- `src/hotkey.js` — руками: сочетание клавиш как текст (`Ctrl+Enter`) и его разбор —
  `parseHotkey`/`formatHotkey` для хранения и поля настроек, `hotkeyFromEvent` для
  записи нажатия, `hotkeyMatches` для события в просмотре. Клавиша читается по
  `KeyboardEvent.code`, то есть по месту на клавиатуре, а не по букве раскладки:
  сочетание, записанное на английской, работает и на русской (там та же клавиша
  печатает `ь`). `key` — только запасной путь для события без кода. Без модификатора
  Ctrl/Alt/Meta сочетание не принимается (одиночная клавиша срабатывала бы при
  чтении), непонятное — возвращается пустым, а не угадывается. Пустая строка — это
  «выключено», и она хранится.
- `src/icon.js` — руками: значок раздела в списке настроек. Регистрируется отдельной
  записью `settings.section.icon` с тем же `id`, что у раздела: строка без такой записи
  получает стандартную заглушку, а с чужим `id` не рисуется вовсе.
- `src/draft.js` — руками: вставка в черновик диалога. Один путь на все случаи: сначала
  `requestDraftInitialization` с `whenDraftExists: 'append'` (новые абзацы, чипы целы),
  иначе фасад композера; при чипах или команде — событие `slash/input-insert-text`,
  потому что `setDraft` расплющивает чипы. Штатной цитаты-карточки (`insertQuote`) здесь
  нет намеренно: она ставится в каретку, а каретку плагину не видно, поэтому доставалась
  бы только пустому черновику — и одно замечание приходило бы карточкой, а другое текстом.
  Свёртка координат (`foldClipboardOffset`, `appendOffset`) скопирована из
  `dsh-better-sidebar`, а не импортирована.
- `src/frontmatter.js` — руками: чтение ведущего YAML-frontmatter в модель свойств
  (скаляры, кавычки, комментарии, блочные и flow-списки, вложенность в один уровень,
  списки карт, блочные скаляры `|`/`>`). Это не YAML-парсер: на анкорах, тегах,
  слишком глубокой вложенности и подозрительном отступе возвращается `null`, и блок
  рисуется дословно, как в файле. Отказ — нормальный исход, а не ошибка.
- `src/*.js` — руками: остальная браузерная часть (настройки, разбор блоков, дифф,
  подписи, настройки-хранилище, fetch).
- `lib/client.js` — **сгенерирован** `scripts/build.mjs` (esbuild). Руками не править,
  исходники — в `src/`. Бандл отдаётся загрузчику как `/plugins/dsh-markdown-diff/client.js`.
- `locale/en.json`, `locale/ru.json`, `locale/zh.json` — руками: название и описание
  плагина для страницы **Plugins** (`meta.title`, `meta.description`). Это не подписи
  интерфейса — те в `src/labels.js`. `meta.detail` не объявлен намеренно: страница берёт
  README, а отдельный документ с картинкой нужен только ради превью.
- `icon.svg` — руками: значок плагина в списке (36 единиц, заливки, без `<style>`/`<text>`).
  Не путать с `src/icon.js`: тот значок рисуется внутри интерфейса и наследует цвет темы.
- `README.md` — русский и короткий: это страница плагина в **Plugins** (ключевые функции и
  цветовая модель, без устройства). `README.en.md` — английский и подробный: устройство,
  проверки, ограничения, установка.
- `test/*.mjs`, `scripts/*.mjs` — проверки: `node scripts/check.mjs`.
- `cordis.patch.yml` — вставка плагина в ростер профиля.

## Правила

- Правки браузерной части — только в `src/`, затем `node scripts/build.mjs`.
- После правок — `node scripts/check.mjs`; он же гоняет реальный git на временном репозитории.
- Плагин заменяет штатный рендерер `.md`: любой новый режим обязан уметь нарисовать
  документ без подсветки. Не оставлять пустую рамку вместо содержимого.
- Разбор адреса и разрешение картинок продублированы из `ui-sidebar-documentpreview`
  намеренно: приватные функции чужого пакета импортировать нельзя, только модули из
  таблицы загрузчика. При расхождении с оригиналом правится копия.
- Не расширять объём: редактирование в предпросмотре, stage/unstage, показ diff по
  строкам, автоотправка сообщений сюда не входят. Комментарий к выделению входит, но
  только как «цитата + замечание в черновик»: он не отправляется сам, не хранится на
  хосте и не переживает перезагрузку вкладки (метки — память поверхности).
- Вставку в композер делать только через `src/draft.js`: `setDraft` на черновике с
  чипами или командой расплющивает их в текст, поэтому там сначала
  `requestDraftInitialization`, а при чипах — событие выделения. Все замечания уходят
  одним и тем же текстом: единообразие важнее украшения, а карточка-цитата недостижима
  на непустом черновике и потому давала бы разный вид у соседних замечаний.
- Подписи кнопок и ошибок — в `src/labels.js` (ru и zh), не в компонентах: язык
  выбирается на каждой отрисовке.
- Сочетание клавиш живёт текстом в `prefs.commentHotkey` (по умолчанию `Ctrl+Enter`,
  пустая строка — выключено) и разбирается только через `src/hotkey.js`. Экран не должен
  толковать `KeyboardEvent` сам: иначе поле настроек и просмотр начнут понимать одно и то
  же по-разному. Непонятное сохранённое значение при чтении откатывается на умолчание.
  Клавиша сравнивается по `event.code`, а не по `event.key`: иначе сочетание перестаёт
  работать при смене раскладки.
- Имя ветки — это ссылка на репозиторий, а не глобальная настройка: `prefs.branch` один
  на всё приложение и переживает переход в другой проект, поэтому поверхность обязана
  сверить его со списком ветвей, как только список пришёл, и заменить незнакомое имя
  подсказкой. Иначе хост отвечает `unknown-ref`, и вместо сравнения читатель видит ошибку.
- Пакет должен ставиться не только из этого каталога: связанный каталог скрывает ошибки
  упаковки, потому что `files` на `link:` не действует. Всё, без чего установленная копия
  не поднимется, — патч, `lib/`, `locale`, `icon.svg`, — перечисляется в `files`; `lib/`
  коммитится, потому что pnpm читает git-пакет без сборки. Сверяет `test/package.test.mjs`,
  фактический список — `npm pack --dry-run --json --cache .tmp-npm-cache`.
- Коммит и push — только по явной просьбе.

## Окружение

- Windows, PowerShell (`pwsh`). Node 24, git 2.55.
- Песочница DSH на Windows запрещает дочерним процессам piped stdio (`spawn EPERM`),
  поэтому git запускается с выводом в файлы, а `scripts/build.mjs` вызывает бинарь
  esbuild напрямую. `node --test` здесь неприменим — свои раннеры в `test/`.
- Подключение в профиль — `~/.dsh/profiles/desktop`: зависимость `link:` + имя пакета
  в `dsh.profile.bundles`; после правок клиента достаточно перезагрузки страницы,
  после правок хоста — перезагрузка профиля. Чужая установка — тем же `install_bundle`:
  `git+<url>#main&path:/plugins/dsh-markdown-diff` (последняя версия) или абсолютный путь.
- Плагин живёт в публичном репозитории `github.com/lag-aa/dsh` каталогом
  `plugins/dsh-markdown-diff`; локально это рабочий каталог репозитория. В спеке установки
  обязателен `path:` — иначе установится корень репозитория.
- `npm pack` по умолчанию пишет кэш в `%LOCALAPPDATA%\npm-cache`, а песочница это
  запрещает (`EPERM`), поэтому проверка упаковки запускается с `--cache .tmp-npm-cache`:
  каталог внутри воркспейса, `.tmp-*` уже в `.gitignore`.
